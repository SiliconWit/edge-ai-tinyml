A bearing rarely fails without warning. For days or weeks it shakes differently, and nobody notices until the motor stops and the line stops with it. You cannot teach a model every fault in advance: faults are rare, each is different, and causing them on purpose is costly or dangerous. Anomaly detection asks an easier question. A model (a rule with adjustable numbers, fitted on a computer and run on the chip) is fitted only to the healthy machine, so it learns what normal looks like and flags what is far from it. This lesson builds that detector: a vibration sensor on a motor, a model fitted to healthy data, and an ESP32 that checks the vibration about twice a second. #AnomalyDetection #PredictiveMaintenance #TinyML

## What We Are Building

<Card title="Vibration Anomaly Detector" icon="star">
An ESP32 with an MPU6050 accelerometer fixed to a small DC motor (or fan). First the device records vibration while the motor runs normally. A Python script on the PC then fits an autoencoder: a model that learns to copy its input through a narrow middle, so it can copy only patterns like the ones it was fitted to. On the ESP32 the model tries to copy each new window of vibration, and the size of its miss is the reconstruction error. When that error passes a threshold, the device lights an LED and publishes an MQTT message.
</Card>

:::tip[Instrument it]
This is predictive maintenance in miniature, and it works only because the sensor is in the right place. Mount the accelerometer rigidly on the bearing housing, in the load zone, aligned with the axis the fault shakes (the [industrial deployment notes](#practical-considerations-for-industrial-deployment) below cover studs and epoxy). The [ESP32 reading the MPU6050](/education/sensor-actuator-interfacing-stm32/) runs the model on-device and raises an [alert only when the pattern changes](https://siliconwit.io), so a motor warns you before a bearing seizes.
:::

## Anomaly Detection vs Classification

<InArticleAd />


A classifier needs labelled examples of every class. A motor gives thousands of healthy hours and almost no failures, so a classifier has nothing to learn the faults from.

An anomaly detector needs only the healthy hours. Think of a night guard who knows the usual sounds of a building. The guard cannot name a new sound, but notices at once that it does not belong. The detector does the same, and it has the guard's limits:

- **It says "different", not "which fault".** A worn bearing, a loose sensor and a new load all raise the same flag. A person must find the cause.
- **It knows only the normal it was taught.** Fit a new bearing, run a different product or let the season change, and the healthy machine looks different. The detector then flags everything until you record the new normal and train it again.
- **It can miss a slow change.** A fault that grows a little each week can stay under the threshold for a long time.

## Autoencoder Architecture for MCUs

<InArticleAd />


A microcontroller has little memory, so the network must be small. It must also be unable to copy everything, or every window would look normal. Four layers of weights do both jobs: 300 inputs, then 64, 16 and 64 values, then 300 outputs.

- **300 inputs** (100 samples x 3 axes): one window fits in a single small array.
- **A middle of 16 numbers** (the bottleneck): the network must describe a whole window with 16 numbers. It learns to do this for normal vibration. A pattern it never saw does not fit through the middle, so it comes out wrong.
- **Total parameters** (the adjustable numbers): $300 \times 64 + 64 + 64 \times 16 + 16 + 16 \times 64 + 64 + 64 \times 300 + 300 = 40892$. After int8 quantization each weight takes one byte ([Model Quantization and Optimization for MCUs](/education/edge-ai-tinyml/model-quantization-optimization-mcu/) explains how). Converted with TensorFlow 2.21 the file was 55,640 bytes: about 40 KB of weights, the 444 biases at 4 bytes, a scale for every output unit, and the file structure. Read the real size from your own converter.

### Data Collection Firmware

The following ESP-IDF firmware captures vibration windows and sends them to the PC over UART for training. Run the motor at its normal operating speed during data collection.

```c
#include <stdio.h>
#include <string.h>
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "driver/i2c_master.h"
#include "esp_log.h"
#include "esp_timer.h"

static const char *TAG = "vibration_collect";

/* I2C and sensor config */
#define I2C_MASTER_SCL_IO    22
#define I2C_MASTER_SDA_IO    21
#define I2C_MASTER_FREQ_HZ   400000
#define MPU6050_ADDR         0x68

/* Data collection parameters */
#define SAMPLE_RATE_HZ       200
#define WINDOW_SIZE          100   /* 0.5 seconds at 200 Hz */
#define NUM_AXES             3     /* Accelerometer only (x, y, z) */
#define NUM_WINDOWS          500   /* Collect 500 normal windows */

static i2c_master_bus_handle_t s_i2c_bus;
static i2c_master_dev_handle_t s_mpu_dev;

/* ---- I2C initialization ---- */

static void i2c_init(void)
{
    i2c_master_bus_config_t bus_cfg = {
        .clk_source = I2C_CLK_SRC_DEFAULT,
        .i2c_port = I2C_NUM_0,
        .scl_io_num = I2C_MASTER_SCL_IO,
        .sda_io_num = I2C_MASTER_SDA_IO,
        .glitch_ignore_cnt = 7,
        .flags.enable_internal_pullup = true,
    };
    ESP_ERROR_CHECK(i2c_new_master_bus(&bus_cfg, &s_i2c_bus));

    i2c_device_config_t dev_cfg = {
        .dev_addr_length = I2C_ADDR_BIT_LEN_7,
        .device_address = MPU6050_ADDR,
        .scl_speed_hz = I2C_MASTER_FREQ_HZ,
    };
    ESP_ERROR_CHECK(i2c_master_bus_add_device(s_i2c_bus, &dev_cfg,
                                               &s_mpu_dev));
}

static void mpu6050_write_reg(uint8_t reg, uint8_t val)
{
    uint8_t buf[2] = {reg, val};
    i2c_master_transmit(s_mpu_dev, buf, 2, 100);
}

static void mpu6050_init(void)
{
    mpu6050_write_reg(0x6B, 0x00); /* Wake up */
    vTaskDelay(pdMS_TO_TICKS(100));
    mpu6050_write_reg(0x1C, 0x08); /* Accel +/- 4g */
    mpu6050_write_reg(0x19, 0x04); /* Sample rate: 1 kHz / (1+4) = 200 Hz */
    mpu6050_write_reg(0x1A, 0x02); /* DLPF 94 Hz: keeps up to Nyquist (100 Hz) */
    ESP_LOGI(TAG, "MPU6050 initialized: 200 Hz, +/- 4g, DLPF 94 Hz");
}

static void mpu6050_read_accel(float *ax, float *ay, float *az)
{
    uint8_t reg = 0x3B;
    uint8_t raw[6];

    i2c_master_transmit_receive(s_mpu_dev, &reg, 1, raw, 6, 100);

    int16_t raw_ax = (int16_t)((raw[0] << 8) | raw[1]);
    int16_t raw_ay = (int16_t)((raw[2] << 8) | raw[3]);
    int16_t raw_az = (int16_t)((raw[4] << 8) | raw[5]);

    /* +/- 4g range: sensitivity = 8192 LSB/g */
    *ax = raw_ax / 8192.0f;
    *ay = raw_ay / 8192.0f;
    *az = raw_az / 8192.0f;
}

/* ---- Data collection ---- */

static float s_window[WINDOW_SIZE][NUM_AXES];

static void capture_window(void)
{
    int64_t interval_us = 1000000 / SAMPLE_RATE_HZ;

    for (int i = 0; i < WINDOW_SIZE; i++) {
        int64_t start = esp_timer_get_time();
        mpu6050_read_accel(&s_window[i][0], &s_window[i][1],
                           &s_window[i][2]);

        while ((esp_timer_get_time() - start) < interval_us) {
            /* spin */
        }
    }
}

static void print_window_csv(int window_idx)
{
    printf("WINDOW,%d\n", window_idx);
    for (int i = 0; i < WINDOW_SIZE; i++) {
        printf("%.4f,%.4f,%.4f\n",
               s_window[i][0], s_window[i][1], s_window[i][2]);
    }
    printf("END\n");
}

/* ---- Main ---- */

void app_main(void)
{
    ESP_LOGI(TAG, "Vibration data collection starting");

    i2c_init();
    mpu6050_init();

    /* Wait for motor to reach steady state */
    ESP_LOGI(TAG, "Waiting 5 seconds for motor to stabilize...");
    vTaskDelay(pdMS_TO_TICKS(5000));

    ESP_LOGI(TAG, "Collecting %d windows at %d Hz...", NUM_WINDOWS,
             SAMPLE_RATE_HZ);

    for (int w = 0; w < NUM_WINDOWS; w++) {
        capture_window();
        print_window_csv(w);

        /* capture_window() never blocks. Give the idle task one tick,
           or the task watchdog reports an error after a few seconds. */
        vTaskDelay(pdMS_TO_TICKS(10));

        if ((w + 1) % 50 == 0) {
            ESP_LOGI(TAG, "Progress: %d/%d windows", w + 1, NUM_WINDOWS);
        }
    }

    ESP_LOGI(TAG, "Collection complete. %d windows captured.",
             NUM_WINDOWS);
}
```

### PC-Side Capture Script

```python
import serial
import numpy as np
import os

PORT = '/dev/ttyUSB0'  # Adjust for your system
BAUD = 115200
OUTPUT_DIR = 'vibration_data/normal'
WINDOW_SIZE = 100
NUM_AXES = 3

os.makedirs(OUTPUT_DIR, exist_ok=True)
ser = serial.Serial(PORT, BAUD, timeout=5)

windows = []
current_window = []
window_idx = -1

print("Capturing vibration data. Run the motor at normal speed.")

while True:
    line = ser.readline().decode('utf-8', errors='ignore').strip()

    if line.startswith('WINDOW,'):
        window_idx = int(line.split(',')[1])
        current_window = []
    elif line == 'END' and len(current_window) == WINDOW_SIZE:
        arr = np.array(current_window, dtype=np.float32)
        windows.append(arr)

        filename = os.path.join(OUTPUT_DIR, f'window_{window_idx:04d}.npy')
        np.save(filename, arr)

        if (window_idx + 1) % 50 == 0:
            print(f"Saved {window_idx + 1} windows")
    elif ',' in line:
        try:
            values = [float(x) for x in line.split(',')]
            if len(values) == NUM_AXES:
                current_window.append(values)
        except ValueError:
            pass

# Save all windows as a single array
all_data = np.array(windows)
np.save(os.path.join(OUTPUT_DIR, 'all_windows.npy'), all_data)
print(f"Total windows saved: {len(windows)}, shape: {all_data.shape}")
```

## Training the Autoencoder

<InArticleAd />


Training runs on the PC, on the 500 normal windows. The script scales every input (subtract the mean, divide by the standard deviation), then asks the network to reproduce its input: in `fit(X_train, X_train)` the target is the input itself. The loss is the mean squared error (MSE), the average squared difference between input and output.

```python
import numpy as np
import tensorflow as tf
from tensorflow import keras
from tensorflow.keras import layers
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt

# Load data
data = np.load('vibration_data/normal/all_windows.npy')
print(f"Data shape: {data.shape}")  # (500, 100, 3)

# Flatten each window: (500, 300)
X = data.reshape(data.shape[0], -1).astype(np.float32)

# Normalize to zero mean, unit variance
X_mean = X.mean(axis=0)
X_std = X.std(axis=0)
X_std[X_std == 0] = 1.0
X_norm = (X - X_mean) / X_std

# Save normalization parameters
np.save('norm_mean.npy', X_mean)
np.save('norm_std.npy', X_std)

# Train/validation split (no test set needed for anomaly detection;
# we evaluate with anomaly data later)
split = int(0.85 * len(X_norm))
X_train = X_norm[:split]
X_val = X_norm[split:]

print(f"Train: {len(X_train)}, Val: {len(X_val)}")

# Build autoencoder
INPUT_DIM = 300

encoder_input = keras.Input(shape=(INPUT_DIM,))
x = layers.Dense(64, activation='relu')(encoder_input)
x = layers.Dense(16, activation='relu')(x)
bottleneck = x

x = layers.Dense(64, activation='relu')(bottleneck)
decoder_output = layers.Dense(INPUT_DIM, activation='linear')(x)

autoencoder = keras.Model(encoder_input, decoder_output)
autoencoder.compile(
    optimizer=keras.optimizers.Adam(learning_rate=0.001),
    loss='mse')

autoencoder.summary()

# Train
history = autoencoder.fit(
    X_train, X_train,
    validation_data=(X_val, X_val),
    epochs=100,
    batch_size=32,
    callbacks=[
        keras.callbacks.EarlyStopping(patience=10,
                                      restore_best_weights=True),
        keras.callbacks.ReduceLROnPlateau(factor=0.5, patience=5),
    ])

# Plot training history
plt.figure(figsize=(8, 4))
plt.plot(history.history['loss'], label='Train Loss')
plt.plot(history.history['val_loss'], label='Val Loss')
plt.xlabel('Epoch')
plt.ylabel('MSE')
plt.title('Autoencoder Training')
plt.legend()
plt.savefig('training_history.png', dpi=100)
print("Training history saved to training_history.png")
```

## Setting the Anomaly Threshold

<InArticleAd />


The model gives a number, not a decision. You must choose how large an error counts as unusual. Set the threshold too low and healthy windows raise flags. Set it too high and real faults pass. A usual rule: take the errors of healthy windows, and add three times their standard deviation (sigma, a measure of spread) to their mean.

Not the training windows: the model was fitted to them, so their errors are smaller than any new window's. Record a quiet baseline: run the capture script on another day with `OUTPUT_DIR = 'vibration_data/baseline'`, while a person confirms the machine is healthy (30 minutes is 3,600 windows). The script uses it, or the validation windows until you have one.

```python
# Errors of healthy windows the model never saw: the quiet baseline,
# or else the validation windows
import os
base_file = 'vibration_data/baseline/all_windows.npy'
if os.path.exists(base_file):
    base = np.load(base_file).reshape(-1, INPUT_DIM)
    X_check = ((base - X_mean) / X_std).astype(np.float32)
else:
    X_check = X_val
reconstructed = autoencoder.predict(X_check)
mse_per_sample = np.mean((X_check - reconstructed) ** 2, axis=1)

error_mean = mse_per_sample.mean()
error_std = mse_per_sample.std()

# Threshold: mean + 3 standard deviations
threshold = error_mean + 3.0 * error_std

print(f"Healthy MSE - mean: {error_mean:.6f}, std: {error_std:.6f}")
print(f"Anomaly threshold (mean + 3*sigma): {threshold:.6f}")
print(f"Healthy windows above it: {np.mean(mse_per_sample > threshold):.2%}")

# Plot error distribution
plt.figure(figsize=(8, 4))
plt.hist(mse_per_sample, bins=50, alpha=0.7, label='Normal errors')
plt.axvline(threshold, color='r', linestyle='--',
            label=f'Threshold ({threshold:.4f})')
plt.xlabel('Reconstruction MSE')
plt.ylabel('Count')
plt.title('Reconstruction Error Distribution (Normal Data)')
plt.legend()
plt.savefig('error_distribution.png', dpi=100)
print("Error distribution saved to error_distribution.png")

# Export threshold as C constant
print(f"\n#define ANOMALY_THRESHOLD  {threshold:.6f}f")
```

If the errors followed a normal distribution, about 99.9% of healthy windows would fall below mean + 3 sigma (only the upper side counts, because a low error is never an anomaly). Real errors usually have a longer tail to the right, so check the histogram and expect more false alarms than this table shows:

| Multiplier | Healthy windows flagged | Effect |
|-----------|-------------------|-------------|
| 2 sigma | ~2.3% | Finds more faults, many false alarms |
| 3 sigma | ~0.13% | A common starting point |
| 4 sigma | ~0.003% | Very few false alarms, may miss small faults |

In a simulation of this setup (500 healthy windows of a 25 Hz motor with noise, the same network and training):

| Threshold taken from | New healthy windows flagged | After a 5% change of load | Alerts per hour (EMA, 3 in a row), 5% change |
|---|---|---|---|
| Training errors, mean + 3 sigma | 5.4% (about 380 an hour) | 24% | 35 |
| 30-minute baseline, mean + 3 sigma | 0.5% | 3.9% | 0 |
| 30-minute baseline, 99.9th percentile | 0.1% | 1.2% | 0 |

At about 7,000 windows an hour, even 0.5% is some 35 flagged windows an hour; the smoothing below turns them into no alert in steady running. Your machine gives other numbers: the share of baseline windows above the threshold is the false-alarm rate you will live with.

### Why most flags are false when faults are rare

A small false alarm rate still gives many false alarms, because the healthy hours are so many. Count one year of a motor that is checked once an hour:

- The year has 8,760 hours. Suppose the motor is faulty for 20 of them and healthy for 8,740.
- The detector catches 95% of the faulty hours: $0.95 \times 20 = 19$ true flags.
- It flags 1% of the healthy hours: $0.01 \times 8740 \approx 87$ false flags.

Of $19 + 87 = 106$ flags, only 19 are real. That is about 18%, fewer than 1 in 5. The detector is not broken: faults are rare, so even a small share of the healthy hours outnumbers them. This is why the firmware below smooths the error and waits for several windows in a row, and why a flag means "go and look", not "stop the machine".

### Quantization and Conversion

def representative_dataset():

### ESP32 Inference Firmware

`ANOMALY_THRESHOLD`, `NORM_MEAN` and `NORM_STD` hold placeholders. Paste your own values from the training script, or every window is judged against the wrong normal.

```c
#include <stdio.h>
#include <string.h>
#include <math.h>
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "driver/i2c_master.h"
#include "driver/gpio.h"
#include "esp_log.h"
#include "esp_timer.h"

#include "tensorflow/lite/micro/micro_interpreter.h"
#include "tensorflow/lite/micro/micro_mutable_op_resolver.h"
#include "tensorflow/lite/micro/schema/schema_generated.h"  /* older TFLM: tensorflow/lite/schema/ */
#include "anomaly_model.h"

static const char *TAG = "anomaly_detect";

/* Hardware config (same as data collection) */
#define I2C_MASTER_SCL_IO    22
#define I2C_MASTER_SDA_IO    21
#define MPU6050_ADDR         0x68

/* Detection parameters */
#define SAMPLE_RATE_HZ       200
#define WINDOW_SIZE          100
#define NUM_AXES             3
#define INPUT_SIZE           (WINDOW_SIZE * NUM_AXES)
#define LED_PIN              GPIO_NUM_2

/* Anomaly threshold (from training script) */
#define ANOMALY_THRESHOLD    0.015000f  /* Replace with your value */

/* Normalization constants (from training script) */
static const float NORM_MEAN[INPUT_SIZE] = {
    /* Paste the 300 mean values from the training export */
    0.0f /* placeholder */
};
static const float NORM_STD[INPUT_SIZE] = {
    /* Paste the 300 std values from the training export */
    1.0f /* placeholder */
};

/* TFLite Micro */
#define TENSOR_ARENA_SIZE  (32 * 1024)
static uint8_t s_tensor_arena[TENSOR_ARENA_SIZE]
    __attribute__((aligned(16)));

/* I2C handles */
static i2c_master_bus_handle_t s_i2c_bus;
static i2c_master_dev_handle_t s_mpu_dev;

/* Sensor window buffer */
static float s_window[WINDOW_SIZE][NUM_AXES];
static float s_flat_input[INPUT_SIZE];

/* ---- I2C and MPU6050 init (same as collection firmware) ---- */

static void i2c_init(void)
{
    /* C++ needs the fields in the order of the ESP-IDF header */
    i2c_master_bus_config_t bus_cfg = {
        .i2c_port = I2C_NUM_0,
        .sda_io_num = I2C_MASTER_SDA_IO,
        .scl_io_num = I2C_MASTER_SCL_IO,
        .clk_source = I2C_CLK_SRC_DEFAULT,
        .glitch_ignore_cnt = 7,
        .flags = { .enable_internal_pullup = true },
    };
    i2c_new_master_bus(&bus_cfg, &s_i2c_bus);

    i2c_device_config_t dev_cfg = {
        .dev_addr_length = I2C_ADDR_BIT_LEN_7,
        .device_address = MPU6050_ADDR,
        .scl_speed_hz = 400000,
    };
    i2c_master_bus_add_device(s_i2c_bus, &dev_cfg, &s_mpu_dev);
}

static void mpu6050_write_reg(uint8_t reg, uint8_t val)
{
    uint8_t buf[2] = {reg, val};
    i2c_master_transmit(s_mpu_dev, buf, 2, 100);
}

static void mpu6050_init(void)
{
    mpu6050_write_reg(0x6B, 0x00);
    vTaskDelay(pdMS_TO_TICKS(100));
    mpu6050_write_reg(0x1C, 0x08); /* +/- 4g */
    mpu6050_write_reg(0x19, 0x04); /* 200 Hz */
    mpu6050_write_reg(0x1A, 0x02); /* DLPF 94 Hz */
}

static esp_err_t mpu6050_read_accel(float *ax, float *ay, float *az)
{
    uint8_t reg = 0x3B;
    uint8_t raw[6];
    esp_err_t err = i2c_master_transmit_receive(s_mpu_dev, &reg, 1,
                                                raw, 6, 100);
    if (err != ESP_OK) {
        return err;   /* raw[] holds nothing valid */
    }
    *ax = (int16_t)((raw[0] << 8) | raw[1]) / 8192.0f;
    *ay = (int16_t)((raw[2] << 8) | raw[3]) / 8192.0f;
    *az = (int16_t)((raw[4] << 8) | raw[5]) / 8192.0f;
    return ESP_OK;
}

/* ---- LED ---- */

static void led_init(void)
{
    gpio_config_t io_conf = {
        .pin_bit_mask = (1ULL << LED_PIN),
        .mode = GPIO_MODE_OUTPUT,
    };
    gpio_config(&io_conf);
    gpio_set_level(LED_PIN, 0);
}

/* ---- Capture and normalize ---- */

/* Returns false if the sensor did not answer, or answered with a flat
   line (a stuck or disconnected sensor), so that a sensor fault is not
   reported as a machine fault */
static bool capture_window(void)
{
    int64_t interval_us = 1000000 / SAMPLE_RATE_HZ;
    float zmin = 1e9f, zmax = -1e9f;

    for (int i = 0; i < WINDOW_SIZE; i++) {
        int64_t start = esp_timer_get_time();
        if (mpu6050_read_accel(&s_window[i][0], &s_window[i][1],
                               &s_window[i][2]) != ESP_OK) {
            return false;
        }
        zmin = fminf(zmin, s_window[i][2]);
        zmax = fmaxf(zmax, s_window[i][2]);
        while ((esp_timer_get_time() - start) < interval_us) {
            /* spin */
        }
    }
    /* Even a still sensor shows a few mg of noise; identical readings
       mean it is stuck */
    return (zmax - zmin) > 0.002f;
}

static void normalize_window(void)
{
    for (int i = 0; i < WINDOW_SIZE; i++) {
        for (int j = 0; j < NUM_AXES; j++) {
            int idx = i * NUM_AXES + j;
            s_flat_input[idx] =
                (s_window[i][j] - NORM_MEAN[idx]) / NORM_STD[idx];
        }
    }
}

/* ---- Anomaly detection task ---- */

static void anomaly_detection_task(void *arg)
{
    /* Initialize TFLite Micro */
    const tflite::Model *model = tflite::GetModel(anomaly_model_tflite);

    static tflite::MicroMutableOpResolver<3> resolver;
    resolver.AddFullyConnected();
    resolver.AddReshape();
    resolver.AddRelu();

    static tflite::MicroInterpreter interpreter(
        model, resolver, s_tensor_arena, TENSOR_ARENA_SIZE);
    if (interpreter.AllocateTensors() != kTfLiteOk) {
        ESP_LOGE(TAG, "AllocateTensors failed: arena or op missing");
        vTaskDelete(NULL);
    }

    TfLiteTensor *input = interpreter.input(0);
    TfLiteTensor *output = interpreter.output(0);

    ESP_LOGI(TAG, "TFLite Micro ready. Arena: %zu bytes",
             interpreter.arena_used_bytes());

    /* Exponential moving average for smoothing */
    float ema_error = 0.0f;
    float ema_alpha = 0.3f;
    bool first_window = true;

    int anomaly_count = 0;
    int normal_count = 0;

    while (1) {
        /* Capture 0.5-second window */
        if (!capture_window()) {
            ESP_LOGE(TAG, "SENSOR FAULT: no data or flat signal");
            gpio_set_level(LED_PIN, 0);
            vTaskDelay(pdMS_TO_TICKS(1000));
            continue;
        }
        normalize_window();

        /* Quantize input */
        float in_scale = input->params.scale;
        int in_zp = input->params.zero_point;
        int8_t *in_data = input->data.int8;

        for (int i = 0; i < INPUT_SIZE; i++) {
            int32_t q = (int32_t)roundf(s_flat_input[i] / in_scale) + in_zp;
            if (q < -128) q = -128;
            if (q > 127) q = 127;
            in_data[i] = (int8_t)q;
        }

        /* Run inference */
        int64_t t_start = esp_timer_get_time();
        if (interpreter.Invoke() != kTfLiteOk) {
            ESP_LOGE(TAG, "Invoke failed");
            continue;
        }
        int64_t t_end = esp_timer_get_time();

        /* Dequantize output and compute reconstruction error */
        float out_scale = output->params.scale;
        int out_zp = output->params.zero_point;
        int8_t *out_data = output->data.int8;

        float mse = 0.0f;
        for (int i = 0; i < INPUT_SIZE; i++) {
            float reconstructed =
                (out_data[i] - out_zp) * out_scale;
            float original =
                (in_data[i] - in_zp) * in_scale;
            float diff = original - reconstructed;
            mse += diff * diff;
        }
        mse /= INPUT_SIZE;

        /* Exponential moving average */
        if (first_window) {
            ema_error = mse;
            first_window = false;
        } else {
            ema_error = ema_alpha * mse + (1.0f - ema_alpha) * ema_error;
        }

        bool is_anomaly = ema_error > ANOMALY_THRESHOLD;

        if (is_anomaly) {
            anomaly_count++;
            gpio_set_level(LED_PIN, 1);
            ESP_LOGW(TAG, "ANOMALY! MSE=%.6f, EMA=%.6f, "
                     "Threshold=%.6f, Infer=%lld us",
                     mse, ema_error, ANOMALY_THRESHOLD,
                     (long long)(t_end - t_start));
        } else {
            normal_count++;
            gpio_set_level(LED_PIN, 0);
            ESP_LOGI(TAG, "Normal. MSE=%.6f, EMA=%.6f, "
                     "Infer=%lld us",
                     mse, ema_error,
                     (long long)(t_end - t_start));
        }

        /* Print statistics every 100 windows */
        if ((anomaly_count + normal_count) % 100 == 0) {
            ESP_LOGI(TAG, "Stats: %d normal, %d anomalies (%.1f%%)",
                     normal_count, anomaly_count,
                     100.0f * anomaly_count
                     / (anomaly_count + normal_count));
        }

        /* capture_window() never blocks. Give the idle task one tick,
           or the task watchdog reports an error after a few seconds. */
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

/* ---- Entry point ---- */

/* This file uses the C++ TFLM API, so it is compiled as C++ (main.cc) */
extern "C" void app_main(void)
{
    ESP_LOGI(TAG, "Vibration anomaly detector starting");

    i2c_init();
    mpu6050_init();
    led_init();

    /* Wait for motor to stabilize */
    ESP_LOGI(TAG, "Waiting 3 seconds for motor to stabilize...");
    vTaskDelay(pdMS_TO_TICKS(3000));

    xTaskCreate(anomaly_detection_task, "anomaly_task",
                8192, NULL, 5, NULL);
}
```

## Real-Time Monitoring Loop

<InArticleAd />


The task checks about two windows each second (each window takes 0.5 seconds to record). One window with a high error is not yet a flag. The firmware keeps an exponential moving average (EMA): each new error moves the average only 30% of the way toward it (alpha = 0.3), so a single spike is damped.

A lasting change is not damped for long. After three windows in a row the EMA has covered $1 - 0.7^3 \approx 66\%$ of the distance to the new error level.

To test the detector, make a mechanical fault while the motor is running:

- **Imbalance:** Attach a small piece of tape or a coin to one blade of a fan.
- **Bearing friction:** Press lightly against the motor shaft with a pencil eraser.
- **Loosening:** Partially detach the MPU6050 from the motor housing.

Expect the MSE to rise at once and the LED to turn on within 1 to 2 seconds. Notice that the third test is not a fault of the motor at all, and the detector flags it the same way. A sensor that stops answering, or sends identical readings, is reported as "SENSOR FAULT" instead; a loose one still looks like a machine fault.

### Check it

Measure the two numbers that matter, on the machine itself:

1. **False alerts.** Run the healthy motor for one hour and count alerts (three windows in a row). Aim for none; alerts per day is the number the people who receive them will judge you by.
2. **Detection and delay.** Make each test fault for two minutes; note the share of windows flagged and the seconds to the LED. A fault never flagged needs another feature (the RMS below), not a lower threshold. If every window is flagged, check that `NORM_MEAN` is not still the placeholder.

## Edge vs Cloud Comparison

<InArticleAd />


The same model could run on a server, with the ESP32 sending raw samples. The delay and current figures below are typical values, not measurements from this build.

| Metric | Edge (ESP32) | Cloud (MQTT + Server) |
|--------|-------------|----------------------|
| Detection latency | 0.5 to 1.5 s (one to three windows) | 1 to 5 s (network + server processing) |
| Bandwidth | 0 bytes (inference local) | 1200 bytes/sec (raw data streaming) |
| Availability | Core inference works offline | Requires network connection |
| Power | ~80 mA (MCU only) | ~160 mA (MCU + Wi-Fi radio) |
| Model update | Requires OTA firmware update | Update model on server, instant |

Deciding on the device suits an alert that must not wait for a network, and poor networks (factory floors with radio interference, remote pump stations); the raw vibration stays on site. A server suits what one device cannot do: comparing hundreds of sensors, or a model too large for the chip.

### When Hybrid Beats Pure Edge

Most real systems do both. The device decides and raises the alert. A server fills three gaps: it trains a new model when the normal changes, it sees a pattern across many machines, and it gives a second opinion on a window whose error is close to the threshold. [Edge-Cloud Hybrid Architectures](/education/edge-ai-tinyml/edge-cloud-hybrid-architecture/) builds all three.

## Integration with IoT Stack (MQTT Alert on Anomaly)

<InArticleAd />


Add MQTT alerting to the detection loop. When an anomaly lasts for 3 or more windows in a row, the device publishes an alert. When the error returns to normal, it publishes a recovery message.

Published does not mean received. This version decides on the device with or without a connection, keeps the alert, and sends it when the connection returns (QoS 1: the broker confirms). A reboot still loses a waiting alert (keep it in NVS if that matters), and `esp_timer_get_time()` counts from start-up, so use SNTP time on a real site.

```c
#include "mqtt_client.h"

extern esp_mqtt_client_handle_t s_mqtt_client;
extern bool s_mqtt_connected;

#define ALERT_TOPIC    "device/anomaly/alert"
#define STATUS_TOPIC   "device/anomaly/status"
#define ALERT_WINDOW_COUNT  3

static int s_consecutive_anomalies = 0;
static bool s_alert_active = false;
static bool s_alert_pending = false;      /* decided, not yet sent */
static bool s_recovery_pending = false;
static char s_alert_payload[256];
static char s_recovery_payload[128];

static void check_and_publish_anomaly(float mse, float ema, bool is_anomaly)
{
    /* 1. Decide on the device, with or without a connection */
    if (is_anomaly) {
        s_consecutive_anomalies++;

        if (s_consecutive_anomalies >= ALERT_WINDOW_COUNT
            && !s_alert_active) {
            snprintf(s_alert_payload, sizeof(s_alert_payload),
                     "{\"status\":\"anomaly\","
                     "\"mse\":%.6f,\"ema\":%.6f,"
                     "\"threshold\":%.6f,"
                     "\"consecutive\":%d,"
                     "\"timestamp\":%lld}",
                     mse, ema, ANOMALY_THRESHOLD,
                     s_consecutive_anomalies,
                     (long long)(esp_timer_get_time() / 1000000));
            s_alert_active = true;
            s_alert_pending = true;
            s_recovery_pending = false;
        }
    } else {
        if (s_alert_active) {
            snprintf(s_recovery_payload, sizeof(s_recovery_payload),
                     "{\"status\":\"normal\","
                     "\"mse\":%.6f,"
                     "\"timestamp\":%lld}",
                     mse,
                     (long long)(esp_timer_get_time() / 1000000));
            s_alert_active = false;
            s_recovery_pending = true;
        }
        s_consecutive_anomalies = 0;
    }

    /* 2. Send what is waiting, alert before recovery */
    if (!s_mqtt_connected) return;
    if (s_alert_pending
        && esp_mqtt_client_publish(s_mqtt_client, ALERT_TOPIC,
                                   s_alert_payload, 0, 1, 0) >= 0) {
        s_alert_pending = false;
        ESP_LOGW(TAG, "MQTT alert published");
    }
    if (s_recovery_pending && !s_alert_pending
        && esp_mqtt_client_publish(s_mqtt_client, STATUS_TOPIC,
                                   s_recovery_payload, 0, 1, 0) >= 0) {
        s_recovery_pending = false;
        ESP_LOGI(TAG, "MQTT recovery published");
    }
}
```

## Practical Considerations for Industrial Deployment

<InArticleAd />


**The flag is advice.** The model is an estimate fitted to past data, and it can be wrong with nothing to show it. Use the flag to send a person or to plan a check. A limit that protects people or the machine (overcurrent, overtemperature, an emergency stop) stays a plain rule in the device or in hardware. The model must never be the only thing that stops a machine.

**What a technician does with an alert.** Check the sensor first (still fixed, cable whole), then the situation (a new load, product, speed or repair changes the normal), then the machine: listen, read the bearing housing temperature with an infrared thermometer, compare with a twin machine. If something changed, plan an inspection; do not stop a healthy line on a flag alone. Record what was found, fault or no fault: those records give the true false-alarm rate, and a confirmed "no fault" is healthy data for the next training.

**Sensor mounting.** The data are only as good as the coupling to the machine. Hot glue serves a prototype; industrial installations use threaded studs, magnets or epoxy, on a flat clean surface as close to the bearing as possible.

**Sampling rate selection.** At 200 Hz with the 94 Hz filter, the detector sees running speed and its first harmonics, where imbalance, misalignment and looseness show. A bearing defect starts at hundreds of hertz to kilohertz and reaches this band only late, so early bearing warning needs a sensor read at several kilohertz (the MPU6050 stops at 1 kHz, and the model input grows with the rate). Keep a plain RMS (root mean square) of each window beside the model: in the simulation above, a 30% rise in running-speed vibration raised the RMS by 27% but was flagged in only 2% of windows, because reconstruction error measures shape more than size.

**Temperature effects.** The MPU6050's offset drifts with temperature. Where the temperature varies widely (outdoors, near heat sources), compensate for it or retrain from time to time.

**A new normal.** After a new bearing, a different product or a change of season, record fresh normal windows and train again. A person must confirm that the machine was healthy while they were recorded. Otherwise the detector learns a fault as normal.

**Multi-axis vs single-axis.** On some machines one axis carries most of the vibration. Fewer axes mean a smaller input and a shorter inference time, so test which axes matter on your machine.

## Exercises

<InArticleAd />


1. **Collect anomaly data and measure detection accuracy.** After training on normal data, make three kinds of fault (imbalance, friction, loosening) and collect 50 windows of each. Plot the MSE of each kind beside the normal distribution. Report the share of faults caught and the share of false alarms at several thresholds.

2. **Implement frequency-domain features.** Compute an FFT of each window and use the magnitude spectrum as the model input. Compare the detection accuracy and model size with the raw samples. Faults of rotating machines often appear as peaks at particular frequencies.

3. **Add a rolling baseline update.** Implement a mechanism where the ESP32 maintains a running average of reconstruction errors over the last 1000 normal windows. If the baseline gradually increases (indicating slow wear), adjust the threshold upward to avoid nuisance alarms while still catching sudden changes. Then name the risk: what kind of fault does this rule hide?

4. **Deploy on STM32 for comparison.** Port the inference firmware to an STM32F4 using the HAL and TFLite Micro. Compare inference latency, memory usage, and power consumption with the ESP32 deployment. Document any differences in the TFLite Micro setup or op resolver configuration.

## Summary

<InArticleAd />


You trained an autoencoder on normal vibration only and used its reconstruction error as an anomaly score, with a threshold judged on a quiet baseline. The model has 40,892 parameters and a quantized file of about 54 KB (measured on a PC); expect a few milliseconds per inference on the ESP32, an estimate to check in your log. The firmware smooths the score, tells a sensor fault from a machine anomaly, and raises an LED and an MQTT alert when the error stays high.

The detector says "different from the normal it was taught". It does not name the fault, it must be taught again when the normal changes, and most of its flags are false when faults are rare. So its flag is advice for a person, and fast protection stays a plain rule.
