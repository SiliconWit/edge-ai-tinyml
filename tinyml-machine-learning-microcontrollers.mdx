A sensor that sends every reading to a server and waits for the answer gets it late, pays for the link in data and power, and stops deciding when the network stops. For a wake word, a gesture or a fault alert, a quarter of a second is often too long. Computed in the microcontroller itself, the answer comes in milliseconds or less, with no network, and the readings never leave the site. The price: the model must fit in the chip's flash and RAM. This lesson walks the whole path once. On your PC you fit a small model to a sine wave with TensorFlow, store its numbers in 8 bits and turn it into a C array; then you run it on an ESP32 and time each prediction. #TinyML #EdgeAI #ESP32

## What is TinyML?

A **model** is a rule with adjustable numbers. The line `y = a*x + b` is a model with two numbers, `a` and `b`. **Training** means a computer adjusts the numbers until the rule fits thousands of examples. **Inference** means using the finished rule: one new input goes in and one answer comes out. Training is heavy work for a PC. Inference is only multiplications and additions, so a microcontroller (MCU) can do it.

TinyML is machine learning (ML) inference on a microcontroller. The difficulty is memory: a server has gigabytes of RAM, and a microcontroller has kilobytes.

<Card title="The Core Idea" icon="star">
Train the model on a PC or a cloud service. Shrink it and convert it into a file that fits in the flash of the MCU. On the MCU, a small program called an interpreter reads the model and computes an answer from live sensor data: a class label, a value, or a score that says how unusual the reading is. Nothing leaves the device.
</Card>

```text
  Model on a server
  Sensor ──Wi-Fi──► Server ──Wi-Fi──► Result
           ~100 ms   ~50 ms   ~100 ms
           Total: ~250 ms, and a network is required

  Model on the microcontroller (TinyML)
  Sensor ──► MCU ──► Result
             about 1 ms to tens of ms
           Total: the same, and it works offline
```

The time on the MCU grows with the model: tens of microseconds for one inference of the 321-number model of this lesson, about 1 ms to tens of milliseconds for a motion or sound model. A whole cycle is longer than one inference: a device that first records one second of sound answers after that second, however fast the model runs.

### Why run the model on the device?

Three more gains: raw data stay on the device and only results are sent; a Cortex-M4 running one inference a second draws a few milliamps; and a 2 USD MCU does work that would otherwise need a 50 USD single-board computer or a paid cloud service.

The cost is size. A model that fits in kilobytes is less accurate than a large model on a server, and changing it means updating the firmware.

## Hardware Constraints

<InArticleAd />


The model shares flash and RAM with your firmware, and the processor sets how long one inference takes. These are common TinyML chips. An FPU (floating-point unit) is hardware for arithmetic with fractional numbers, which is slow without it.

| MCU | CPU | Clock | Flash | SRAM | FPU | Typical Use |
|-----|-----|-------|-------|------|-----|-------------|
| ESP32 (Xtensa LX6) | Dual-core | 240 MHz | 4 MB | 520 KB | Yes | Wi-Fi/BLE + ML |
| STM32F4 (Cortex-M4F) | Single-core | 168 MHz | 1 MB | 192 KB | Yes | Industrial ML |
| RPi Pico (Cortex-M0+) | Dual-core | 125 MHz (SDK default) | 2 MB | 264 KB | No | Low-cost ML |
| nRF52840 (Cortex-M4F) | Single-core | 64 MHz | 1 MB | 256 KB | Yes | BLE + ML |

**Practical limits for model size:**
- Flash: the model is stored as a constant C array beside the firmware. A usual budget is 50 KB to 500 KB.
- RAM: the interpreter needs room for the input, the output and the results between layers. TensorFlow Lite for Microcontrollers (TFLM) takes it from one fixed array, the tensor arena. A tensor is an array of numbers. Budget 20 KB to 100 KB.
- Compute: the time grows with the number of multiplications. With 8-bit integers (int8) a model runs 2 to 4 times faster than with 32-bit floating-point numbers (float32) on a Cortex-M4 with CMSIS-NN, Arm's library of fast routines.

## The ML Pipeline for Microcontrollers

<InArticleAd />


Every project in this course follows six steps. The first four run on the PC and the last two on the MCU. If step 6 shows too little accuracy, return to step 2.

<Steps>
1. **Collect or generate training data.**
   Here we generate sine wave data with noise. Later lessons use real sensor data.

2. **Train a model in TensorFlow (or PyTorch, scikit-learn).**
   The model must be small enough for the chip.

3. **Convert to TensorFlow Lite (.tflite).**
   The converter writes one binary file. At this step, quantization stores each number in 8 bits in place of 32, so a model of thousands of weights shrinks up to four times and runs faster.

4. **Convert .tflite to a C array.**
   The `xxd` utility (or a Python script) turns the binary into a `const unsigned char[]` that compiles into firmware.

5. **Write firmware that runs the TFLM interpreter.**
   Declare a tensor arena, load the model, call the interpreter, and read the output tensor.

6. **Flash, run, and evaluate.**
   Compare the predictions with the true values and log the inference time.
</Steps>

## Project: Sine Wave Predictor on ESP32

<InArticleAd />


We will train a tiny neural network to approximate `y = sin(x)` over `[0, 2*pi]`. A neural network is built from layers; each multiplies its inputs by weights, adds a bias, and passes the sums on. The weights and biases are the adjustable numbers. This usual first TinyML program needs only an ESP32 and a serial monitor, and uses every step of the pipeline.

### Step 1: Train the Sine Model in Python

Create a file called `train_sine_model.py` on your PC.

```python
# train_sine_model.py
# Train a tiny sine wave regression model and export to TFLite (int8)

import numpy as np
import tensorflow as tf

# Generate training data
np.random.seed(42)
x_values = np.random.uniform(0, 2 * np.pi, 1000).astype(np.float32)
y_values = np.sin(x_values).astype(np.float32)

# Add a small amount of noise to make training more realistic
y_values += 0.1 * np.random.randn(1000).astype(np.float32)

# Split into train and validation
x_train, x_val = x_values[:800], x_values[800:]
y_train, y_val = y_values[:800], y_values[800:]

# Define a small fully connected model
# Three layers of 16, 16 and 1 units: 321 adjustable numbers in total
model = tf.keras.Sequential([
    tf.keras.layers.Dense(16, activation='relu', input_shape=(1,)),
    tf.keras.layers.Dense(16, activation='relu'),
    tf.keras.layers.Dense(1)
])

model.compile(optimizer='adam', loss='mse', metrics=['mae'])
model.summary()

# Train
history = model.fit(
    x_train, y_train,
    epochs=500,
    batch_size=32,
    validation_data=(x_val, y_val),
    verbose=1
)

# Save the Keras model
model.save('sine_model.keras')
print("Keras model saved.")

# Convert to TFLite with int8 quantization
# The converter runs these 100 examples to learn the range of the values,
# which it needs to map them onto 8-bit numbers
def representative_dataset():
    for i in range(100):
        yield [np.array([[x_train[i]]], dtype=np.float32)]

converter = tf.lite.TFLiteConverter.from_keras_model(model)
converter.optimizations = [tf.lite.Optimize.DEFAULT]
converter.representative_dataset = representative_dataset
converter.target_spec.supported_ops = [tf.lite.OpsSet.TFLITE_BUILTINS_INT8]
converter.inference_input_type = tf.int8
converter.inference_output_type = tf.int8

tflite_model = converter.convert()

# Save the quantized model
with open('sine_model_int8.tflite', 'wb') as f:
    f.write(tflite_model)

print(f"TFLite model size: {len(tflite_model)} bytes")

# Quick validation using the TFLite interpreter
interpreter = tf.lite.Interpreter(model_content=tflite_model)
interpreter.allocate_tensors()

input_details = interpreter.get_input_details()
output_details = interpreter.get_output_details()

# Get quantization parameters
input_scale = input_details[0]['quantization'][0]
input_zero_point = input_details[0]['quantization'][1]
output_scale = output_details[0]['quantization'][0]
output_zero_point = output_details[0]['quantization'][1]

print(f"Input scale: {input_scale}, zero_point: {input_zero_point}")
print(f"Output scale: {output_scale}, zero_point: {output_zero_point}")

# Test a few values
test_x = np.array([0.0, 0.5, 1.0, 1.57, 3.14, 4.71, 6.28], dtype=np.float32)
for x in test_x:
    # Quantize input; clip, or an x outside the converter's range wraps around
    x_q = np.int8(np.clip(np.round(x / input_scale + input_zero_point), -128, 127))
    interpreter.set_tensor(input_details[0]['index'], np.array([[x_q]], dtype=np.int8))
    interpreter.invoke()
    y_q = interpreter.get_tensor(output_details[0]['index'])[0][0]
    # Dequantize output; int() first, or NumPy overflows in int8
    y_pred = (int(y_q) - output_zero_point) * output_scale
    y_actual = np.sin(x)
    print(f"x={x:.2f}  predicted={y_pred:.4f}  actual={y_actual:.4f}  error={abs(y_pred - y_actual):.4f}")
```

Run this script:

```bash
pip install tensorflow numpy
python train_sine_model.py
```

You should see a model summary showing 321 parameters ($1 \times 16 + 16 = 32$, $16 \times 16 + 16 = 272$, and $16 \times 1 + 1 = 17$) and the size of the TFLite file. With TensorFlow 2.21 the file was 3,464 bytes, most of it the description of the layers. The validation MAE (mean absolute error) should be under 0.15 (the label noise keeps it above about 0.08). Training starts from random weights, and in three of our eleven runs it stuck near 0.30, fitting only part of the wave; run the script again if you see that.

The printed input scale and zero point (for example 0.0243 and -128) turn x into an int8: $q = x / \text{scale} + \text{zero point}$. So 127 means x = 255 × 0.0243 = 6.20, the largest x the converter saw; a larger x has no code, so the script clips.

If your TensorFlow no longer has `tf.lite.Interpreter`, use `pip install ai-edge-litert` and `from ai_edge_litert.interpreter import Interpreter` (LiteRT is the new name of TensorFlow Lite).

### Step 2: Convert .tflite to a C Header

Use the `xxd` utility to turn the binary into a C array.

```bash
xxd -i sine_model_int8.tflite > sine_model_data.h
```

This produces a file like:

```c
// sine_model_data.h (auto-generated by xxd)
unsigned char sine_model_int8_tflite[] = {
  0x20, 0x00, 0x00, 0x00, 0x54, 0x46, 0x4c, 0x33,
  // ... hundreds of bytes ...
};
unsigned int sine_model_int8_tflite_len = 2480;
```

The length 2480 is an example. Now add `const`, so the array stays in flash and is not copied to RAM, and split it into a header and a source file:

```c
// sine_model_data.h
#ifndef SINE_MODEL_DATA_H
#define SINE_MODEL_DATA_H

extern const unsigned char sine_model_int8_tflite[];
extern const unsigned int sine_model_int8_tflite_len;

#endif
```

And the corresponding `.c` file:

```c
// sine_model_data.c
#include "sine_model_data.h"

const unsigned char sine_model_int8_tflite[] = {
  0x20, 0x00, 0x00, 0x00, 0x54, 0x46, 0x4c, 0x33,
  // ... paste the full array from xxd output ...
};
const unsigned int sine_model_int8_tflite_len = 2480;
```

### Step 4: Firmware (ESP-IDF C with TFLM)

The TFLM API is C++, so the firmware is in `main.cc`. ESP-IDF calls `app_main` from C code, so the function is declared with `extern "C"` as shown.

```cpp
// main/main.cc
// Sine wave predictor using TensorFlow Lite for Microcontrollers on ESP32

#include <cstdio>
#include <cmath>
#include "esp_log.h"
#include "esp_timer.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

#include "tensorflow/lite/micro/micro_mutable_op_resolver.h"
#include "tensorflow/lite/micro/micro_interpreter.h"
// Older esp-tflite-micro versions: tensorflow/lite/schema/schema_generated.h
#include "tensorflow/lite/micro/schema/schema_generated.h"

#include "sine_model_data.h"

static const char *TAG = "sine_predictor";

// Tensor arena: working memory for the interpreter.
// Size depends on the model. 4 KB is generous for this tiny model.
constexpr int kTensorArenaSize = 4 * 1024;
alignas(16) static uint8_t tensor_arena[kTensorArenaSize];

extern "C" void app_main(void) {
    ESP_LOGI(TAG, "Sine wave predictor starting");

    // Load the model from the C array
    const tflite::Model *model = tflite::GetModel(sine_model_int8_tflite);
    if (model->version() != TFLITE_SCHEMA_VERSION) {
        ESP_LOGE(TAG, "Model schema version mismatch: got %lu, expected %d",
                 model->version(), TFLITE_SCHEMA_VERSION);
        return;
    }

    // Register only the ops this model uses (keeps binary small).
    // The converter folds each ReLU into its fully connected layer.
    static tflite::MicroMutableOpResolver<1> resolver;
    if (resolver.AddFullyConnected() != kTfLiteOk) {
        ESP_LOGE(TAG, "Could not register FullyConnected");
        return;
    }

    // Build the interpreter
    static tflite::MicroInterpreter interpreter(model, resolver,
                                                 tensor_arena, kTensorArenaSize);
    TfLiteStatus allocate_status = interpreter.AllocateTensors();
    if (allocate_status != kTfLiteOk) {
        ESP_LOGE(TAG, "AllocateTensors() failed");
        return;
    }

    // Get input and output tensor pointers
    TfLiteTensor *input = interpreter.input(0);
    TfLiteTensor *output = interpreter.output(0);

    // Log tensor details
    ESP_LOGI(TAG, "Input type: %d, shape: [%d, %d]",
             input->type, input->dims->data[0], input->dims->data[1]);
    ESP_LOGI(TAG, "Output type: %d, shape: [%d, %d]",
             output->type, output->dims->data[0], output->dims->data[1]);

    // Get quantization parameters
    float input_scale = input->params.scale;
    int32_t input_zero_point = input->params.zero_point;
    float output_scale = output->params.scale;
    int32_t output_zero_point = output->params.zero_point;

    ESP_LOGI(TAG, "Input  scale=%.6f  zero_point=%d", input_scale, (int)input_zero_point);
    ESP_LOGI(TAG, "Output scale=%.6f  zero_point=%d", output_scale, (int)output_zero_point);

    // Run inference over a sweep of x values
    ESP_LOGI(TAG, "");
    ESP_LOGI(TAG, "%-8s %-12s %-12s %-12s %-10s", "x", "predicted", "actual", "error", "time_us");

    const int num_points = 50;
    float total_error = 0.0f;
    int64_t total_time_us = 0;

    for (int i = 0; i < num_points; i++) {
        float x = (2.0f * M_PI * i) / num_points;

        // Quantize the input, clamped so it cannot wrap around
        int32_t q = (int32_t)roundf(x / input_scale) + input_zero_point;
        if (q < -128) q = -128;
        if (q > 127) q = 127;
        input->data.int8[0] = (int8_t)q;

        // Run inference and time it
        int64_t start = esp_timer_get_time();
        TfLiteStatus invoke_status = interpreter.Invoke();
        int64_t end = esp_timer_get_time();

        if (invoke_status != kTfLiteOk) {
            ESP_LOGE(TAG, "Invoke failed at x=%.2f", x);
            continue;
        }

        // Dequantize the output
        int8_t y_quantized = output->data.int8[0];
        float y_predicted = (y_quantized - output_zero_point) * output_scale;
        float y_actual = sinf(x);
        float error = fabsf(y_predicted - y_actual);

        int64_t inference_us = end - start;
        total_error += error;
        total_time_us += inference_us;

        ESP_LOGI(TAG, "%-8.3f %-12.4f %-12.4f %-12.4f %-10lld",
                 x, y_predicted, y_actual, error, inference_us);
    }

    ESP_LOGI(TAG, "");
    ESP_LOGI(TAG, "Average error: %.4f", total_error / num_points);
    ESP_LOGI(TAG, "Average inference time: %lld us", total_time_us / num_points);
    ESP_LOGI(TAG, "Total arena used: %zu bytes", interpreter.arena_used_bytes());
    ESP_LOGI(TAG, "Model size: %u bytes", sine_model_int8_tflite_len);

    // Keep the task alive
    while (1) {
        vTaskDelay(pdMS_TO_TICKS(10000));
    }
}
```

### Expected Output

The serial output is a table of 50 points. Expect these values on an ESP32 at 240 MHz (the time and the arena are estimates, so trust your own output):

| Metric | Expected value |
|--------|---------------|
| Model size (int8 .tflite) | about 3.4 KB (3,464 bytes with TensorFlow 2.21) |
| Tensor arena used | ~1.2 KB (estimate) |
| Average inference time | 30 to 80 microseconds (estimate) |
| Average absolute error | 0.015 to 0.05 (three good training runs on a PC) |

At 50 microseconds an inference, the ESP32 could make 20,000 predictions a second. That holds only for a model this small.

### Check it

1. **Same model, same answer.** The chip's ninth point is x = 1.005. Put 1.005 in `test_x` and run the script: the PC and the chip should agree within one output step (about 0.008). A larger difference means an error in the quantize or dequantize lines.
2. **The right file.** "Model size" must equal the size of `sine_model_int8.tflite` (`ls -l`); if not, the array is from an older model.
3. **The arena.** Set `kTensorArenaSize` to the printed arena size plus 16 bytes and check that `AllocateTensors()` still succeeds.

In the field the input is a sensor reading, and it can leave the training range. The clamp stops the int8 code from wrapping, but outside its range the model knows nothing. Treat such an input as "no answer".

## Understanding the TFLM Components

<InArticleAd />


### The Model (FlatBuffer)

A `.tflite` file is a FlatBuffer, a binary format that a program reads in place without unpacking. It holds the list of operations in order, the trained weights (as int8), and the shape and scale of every tensor. As a `const` C array it stays in flash, and the interpreter reads it there.

### The Op Resolver

```cpp
static tflite::MicroMutableOpResolver<1> resolver;
resolver.AddFullyConnected();
```

An op (operation) is one kind of calculation in the model, such as a fully connected layer. The op resolver tells the interpreter which code runs each op. `<1>` is the largest number of ops, and each `Add...()` call links in the code for one. This model needs one: the converter merges each ReLU into its layer, and int8 input and output need no quantize op. A missing op makes `AllocateTensors()` fail with a message that names it. The old `AllOpsResolver`, now removed from TFLM, linked every op and added 100 KB or more.

### The Tensor Arena

```cpp
constexpr int kTensorArenaSize = 4 * 1024;
alignas(16) static uint8_t tensor_arena[kTensorArenaSize];
```

The interpreter never calls `malloc`: a device that runs for months must not run out of memory, so the input, the output and the results between layers all come from this one array. `alignas(16)` puts it on the 16-byte boundary that fast vector instructions need. Too small, and `AllocateTensors()` fails at start, where you see it; too large wastes RAM. Print `interpreter.arena_used_bytes()` and set the size a little above it.

### The Interpreter

The `MicroInterpreter` reads the model and places the tensors in the arena. On each `Invoke()` call it runs the ops in order and writes the result to the output tensor. No memory is allocated after `AllocateTensors()`.

## Quantization: Float32 vs Int8

<InArticleAd />


The model was trained with float32 numbers, and the converter stored every weight in 8 bits. An activation is a result between two layers. Sizes and errors were measured with TensorFlow 2.21 (one run, error against the true sine at the firmware's 50 points); speed and RAM are estimates:

| Property | Float32 Model | Int8 Model |
|----------|---------------|------------|
| Weight precision | 32-bit float | 8-bit integer |
| Model file size | 3,252 bytes | 3,464 bytes |
| Inference speed on ESP32 | ~120 us | ~50 us |
| RAM for activations | ~4 KB | ~1.2 KB |
| Mean error | 0.028 | 0.032 |

The int8 model is faster on a chip with fast integer routines, and its error is a little higher. Its file is not smaller: the 321 numbers shrink from 1,284 bytes to 420 (biases stay 32-bit), but every tensor gains a scale and a zero point. The gain grows with the model: in a second test, 4,353 parameters gave an int8 file 2.4 times smaller, and 66,561 parameters 3.6 times. Here the loss of accuracy does not matter. For larger models it needs care, as the lesson on [model quantization](/education/edge-ai-tinyml/model-quantization-optimization-mcu/) shows.
